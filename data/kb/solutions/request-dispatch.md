# Request and dispatch management

## What it does

The request and dispatch area gives the business one queue for every service request, whichever channel it came from. Each request shows who accepted it, and likely duplicates are flagged so two technicians are not sent to the same fault. When the day changes, it suggests schedule revisions that respect site access windows and skills. The dispatcher reads each suggestion and decides.

## What is included

- One shared request queue fed from calls, messages and email.
- Duplicate hints when a new request matches an open one by site, device and symptom.
- An acceptance owner recorded for every request.
- Dispatch suggestions that show which visits could move and why.
- Site access windows and skill constraints applied before a suggestion is shown.

## What it does not do

It does not merge requests without a coordinator's decision. It does not reassign technicians automatically. It does not require customers to use a portal.

## Effect inputs

The estimate uses requests per week and the staff minutes it takes to take in and assign one request, today. The new figure assumes one shared queue. The answer then names the staff time behind the largest share of the estimate.
