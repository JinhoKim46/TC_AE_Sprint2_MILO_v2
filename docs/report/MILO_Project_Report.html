MILO: a diagnosis chatbot that shows its work

MILO answers questions about how a small service business runs its work. It finds passages in a knowledge base, cites them, uses tools to record facts and calculate savings, and shows every step it took. The data is fictional. The project was built milestone by milestone to learn the stack and to be measured at each step.

How MILO works, end to end

One question goes through five stages. Each stage is recorded in a trace, so the chat can show the path and the dashboard can count it.

The kit asks for 2 medium and 1 hard bonus. Three medium items are met. The hard item is partly met, so the full bonus depends on how the judge result is counted.

Limits, stated plainly

  • Sixteen answerable questions per split. Every interval is wide. Differences under about 0.2 nDCG are not reliable.
  • The judge disagreed with the labels in about 18 per cent of items (kappa 0.60, lower bound 0.29), just under the threshold. The labels were written by a model, so this measures model agreement, not human agreement.
  • The M2 filter was chosen on dev after one revision. It is reported as unconfirmed, and the test split was not read again.
  • Duplicate passages between articles were measured on dev and did not affect the top five. Two de-duplication fixes were tested and not adopted.
  • Ten attacks and one model. A zero says these attacks failed, not that the system is secure.
  • The database connection uses the admin role. A limited role is needed before any real data.
  • No browser screen recording has been made. The manual checklist in M6 is for the presenter to tick.

Demo storylines for the evaluation

Four scripted conversations are in data/demo_storylines.json and are served at /api/demo. Each one shows a different part of the system.

  • The same printer, two technicians. A duplicate-dispatch story: sources, a savings estimate with a range, and a fact recorded from the owner's words.
  • We have toner, but nobody can find it. The consumables area, with the calculation done in code.
  • When MILO should not answer. A question the knowledge base cannot answer. MILO says what is not established, and the confidence line shows a weak match.
  • A change that needs your approval. The destructive tool is refused until approval, and the card shows why.

Reproduce the results

  • Checks: make check (lint, format, 78 offline tests), make contract (kit contract, 9 groups).
  • Replays with no model call: make eval-retrieval-replay, make eval-test-replay, make eval-advanced-replay.
  • Run the app: MILO_LIVE=1 MILO_STORE=postgres uv run python -m milo.serve, then open / for the chat and /dashboard for the overview.
