# T0 lesson: the scaffold

## Context

Before any RAG code, a project needs three things: a way to run checks in one command, a fixed **interface** that
tests can hold the app to, and a model client that cannot spend money by accident. The Sprint 2 kit supplies the
interface as a contract test suite: `build_app(chat_model, embeddings, tools_backend) -> App` with `ingest` and
`ask`. Every later milestone makes more of those tests pass.

## What was built

| Piece | Where | Why |
|---|---|---|
| uv project, `make check` (ruff lint and format, offline pytest with sockets blocked) | `pyproject.toml`, `Makefile` | One command says whether the repo is healthy |
| `make kit-sync`, `make contract` | `Makefile` | Copies the kit's tests in (untracked, the repo is public) and runs them against `milo.app:build_app` |
| The interface's data shapes | `src/milo/types.py` | `Document`, `Source`, `ToolResult`, `Response`, `ChatReply`: MILO's own copies, so the app never imports the kit |
| A placeholder `build_app` | `src/milo/app.py` | It answers "not built yet" without a model call, so the suite can run end to end |
| The model client | `src/milo/llm.py` | LangChain `ChatOpenAI` with the OpenRouter base URL, wrapped in `LangChainChat`, which turns a LangChain `AIMessage` into the kit's `ChatReply` (content, tool calls, token usage) |

Two LangChain ideas show up already:

- **`ChatOpenAI` works with any OpenAI-compatible server.** OpenRouter speaks the OpenAI API, so `base_url` plus an
  OpenRouter key and a model slug such as `anthropic/claude-haiku-5.5` is all it takes.
- **LangChain ships fake chat models for tests.** `FakeMessagesListChatModel` returns scripted `AIMessage`s, so the
  adapter is tested offline with real LangChain types.

## How to read the result

- `make check`: 5 passed. Two tests prove the live client refuses without `MILO_LIVE=1` or without a key, one that it
  points at OpenRouter, one that the adapter returns the kit's reply shape, and one that `build_app` has the interface.
- `make contract`: 2 passed, 7 failed. The passes are hollow: "abstain on empty retrieval" passes because the
  placeholder never calls the model, and "identity not from arguments" passes because no tool runs. The 7 failures are
  the roadmap: sources (M1), tools (M3), security (M4), errors (M5), threads and cost (M1, M3).
- One warning was investigated rather than silenced blindly: building `ChatOpenAI` creates (never connects) a socket
  to probe IPv6 support. The socket block stays on; that one test marks the probe as expected.
